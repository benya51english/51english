# 51 English: сборка этапа 6

Сайт обычный статический (без сборки). Без настройки облака он работает как раньше: прогресс хранится на устройстве, форм входа нет.

## Как включить аккаунты и облачный прогресс
1. **Сначала решите, где будет база** (см. «Закон о персональных данных» ниже).
2. Поднимите Supabase-совместимый сервер и в его SQL Editor выполните `supabase/schema.sql` (его можно запускать повторно). Сначала проверьте всё на тестовом проекте без реальных пользователей.
3. В настройках Authentication: Site URL = адрес вашего сайта, в Redirect URLs добавьте тот же адрес; включите подтверждение email; настройте свой SMTP (встроенная почта Supabase ограничена и не для боевого запуска).
4. В `js/config.js` вставьте **Project URL** и **anon (public) key**. `service_role` key в сайт и репозиторий не класть никогда.
5. Если адрес базы не `*.supabase.co`, исправьте `connect-src` в `_headers`.
6. Заполните и согласуйте с юристом `privacy.html`.
7. Опубликуйте на Netlify и пройдите чек-лист ниже.

## Как это устроено
- Одна таблица `progress`: строка на пользователя, прогресс в jsonb. Row Level Security: пользователь видит и меняет только свою строку.
- При входе локальный и облачный прогресс объединяются (уроки по объединению, XP пересчитывается по пройденным урокам). Данные другого аккаунта с этого устройства не подмешиваются.
- «Удалить аккаунт» вызывает функцию `delete_my_account()` и стирает данные.

## Известные ограничения
- Прогресс отправляет сам браузер, значит технически его можно подделать. Для косметических наград это допустимо; перед рейтингами, соревнованиями и платным доступом XP и права нужно считать на сервере.
- Избранное и ошибки сливаются объединением: удалённое на одном устройстве может вернуться с другого.
- Оплаты и подписок нет.

## Закон о персональных данных (важно для аудитории из России)
Email и привязанный к нему прогресс считаются персональными данными. По ч. 5 ст. 18 152-ФЗ при первичном сборе данных граждан РФ базы должны находиться на территории РФ; за нарушение предусмотрены штрафы (ст. 13.11 КоАП) и возможна блокировка. Обычное облако Supabase находится за рубежом, поэтому для российских пользователей лучше: self-hosted Supabase на сервере в РФ (код сайта не меняется, меняется только URL) или российский облачный провайдер, и почтовые уведомления тоже отправлять через российский SMTP. Также нужны политика, согласие и, как правило, уведомление Роскомнадзора. Всё это согласуйте с юристом.

## Чек-лист проверки
1. Регистрация → письмо → подтверждение → вход.
2. Пройдите урок на телефоне, войдите с компьютера: прогресс должен подтянуться.
3. Выход очищает данные на устройстве; вход под другим аккаунтом не показывает чужой прогресс.
4. Сброс пароля по ссылке из письма.
5. Удаление аккаунта; повторная регистрация с тем же email.
6. Попытка прочитать чужую строку через консоль браузера должна вернуть пусто (проверка RLS).
